# Local PDF CBT — Roadmap

- 기준일: 2026-09-01
- 문서 버전: `0.1.5`
- 기준: [PROJECT_BIBLE](PROJECT_BIBLE.md)
- 현재 위치: **Unit 1.5 PDF 확대·축소·너비 맞춤 구현·기능 검증 통과 / 최종 종료 검사 15/18로 전체 완료 보류**
- 미완료 상태: **Unit 0.4의 간헐적 종료 오류가 최종 Unit 1.5 검사에서 재현되어 OPEN-09 미해결, Unit 1.0 미착수 유지**. Unit 1.6 및 이후는 시작하지 않는다.

## 상태와 진행 규칙

`작성 완료·승인 대기`는 산출물을 만들었지만 사용자가 승인하지 않은 상태다. `승인 대기`는 착수 조건이 아직 충족되지 않았다는 뜻이다. `미착수`는 구현·시험을 하지 않았다는 뜻이며 `향후`는 MVP 범위 밖이다. 코드 Unit의 `완료`는 구현·검증·구조 검토·10항목 완료 기록을 모두 갖춘 경우에만 사용한다.

사용자가 요청한 Unit 범위만 개발한다. 선행 Unit의 결과와 부채를 확인하고 시작한다. 구조 검토에서 문제가 발견되면 필요한 수정 내용을 먼저 기록하고 기능 추가 전에 해결한다. 단계 완료가 다음 단계의 자동 착수를 뜻하지 않는다.

## 원안에서 조정한 부분과 이유

| 변경 | 이유 |
| --- | --- |
| 첫 MVP를 검증된 단일 페이지·단일 문제·단일 열로 제한하는 제안 | 범용 자동 변환과 Phase 4 문제 분리 유보를 동시에 보장할 수 없기 때문 |
| Unit 1.0 샘플·입력 정책, 1.6 PDF 기초 통합 검증 추가 | 실제 파일 형식·오류·메모리·오프라인 자산 문제를 분석 기능 전에 확인 |
| Unit 2.0 구조 검토, 2.1 텍스트 품질 분류 포함 | 좌표·데이터 경계를 정하고 스캔/불량 텍스트를 무조건 분석하지 않도록 함 |
| Unit 2.5 Debug Overlay를 2.2 직후 실행 | bbox 변환 오류를 키워드·영역 추정 오류와 분리하기 위해. 번호는 원안 추적을 위해 유지 |
| Unit 2.6 지원 형식·실패 처리 검증 추가 | 키워드 검출 성공만으로 안전한 가림을 선언할 수 없음 |
| Unit 3.0 상태 계약 검토, 3.7 MVP 통합 검증 추가 | 공개 시점·미확정 정답·파일 교체·패키징에 따른 누출과 오채점 방지 |
| Phase 4에서 수동 보정 → 자동 분리 → 페이지 연결 순으로 배치 | 자동 인식에 실패해도 사용할 수 있는 보정 기반을 먼저 마련 |
| 저장·오답·시험·통계·OCR·AI를 Phase 5~10으로 구체화 | 의존성과 구조 검토 시점을 명시하고 현재 범위의 팽창을 방지 |

사용자가 Unit 1.5와 앞서 검토한 Viewer 배치 아이디어 포함을 명시적으로 요청했다. 이번에는 50–200% 배율·너비 맞춤·고유 회전·DPI·창 크기·Canvas 상한과 해당 조작 UI만 추가했다. 페이지 도구 하단 이동, 좌우 보조 이동, 중복 성공 행 제거와 footer 원본 불변 안내를 함께 채택했으며 ADR-022에 기록했다. 이 요청을 Unit 1.0 전체 샘플 작업이나 Text Layer·분석·CBT 기능의 승인으로 확대하지 않았다.

## Phase 0 — Foundation

| Unit | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 0.1 | 요구사항 검토·Project Bible와 개발 문서 5개 | 충돌·누락·위험·MVP 경계·후속 계획·완료 기록 작성. 당시 산출물은 문서만 | 완료 |
| 0.2 | Electron + Vite + Vanilla JS 프로젝트 생성 | Windows 11 x64·버전 고정·ESM/CJS·Packager 설정·개발/로컬 빌드 연결 확인; 상세는 CHANGELOG | 완료 |
| 0.3 | 기본 Application Shell | 한국어 빈 화면·상태 영역·창 크기 대응; PDF/CBT 기능 선행 구현 없음. 실제 개발/빌드 자산 창과 크기별 배치 확인; 상세는 CHANGELOG | 완료 |
| 0.4 | 개발/빌드 환경 검증 | 개발·빌드·Windows x64 ASAR 실행, 서버 없는 앱 네트워크 차단 조건, 격리·CSP·권한·탐색·종료, 새 복사본 재설치; 오류 없음. 종료 GPU 진단 미해결; 상세 조건은 CHANGELOG | 검증 중 |

**Phase 통과 조건:** 보안 경계와 재현 가능한 실행·빌드 절차가 문서화되어야 한다. HTML 번들만 만들어졌다고 Electron 패키지 검증이 끝난 것은 아니다. 서명·공개 배포·자동 업데이트는 범위 밖이며, 실행 가능한 로컬 테스트 패키지를 대상으로 한다.

Unit 0.4에서 개발/빌드 자산/패키지의 실제 창, ASAR 포함 범위, 독립 복사본 실행, 앱 전용 네트워크 차단 조건과 보안 거부 경로를 검증했다. Node 경계 검사 16개와 Electron 통합 검사 3개는 통과했고 Windows 종료 반복 검사도 추가했다. **빠른 종료에서 간헐적인 GPU 오류 로그가 재현되어 Unit 0.4와 Phase 0 완료는 보류한다.** PDF·worker·OCR/AI·향후 저장의 검증까지 완료한 것은 아니다.

Unit 0.3에서 관찰한 GPU 로그가 패키지 창을 표시하고 250ms 후 닫을 때 다시 나타났다. 종료 전 stderr는 비어 있었고 닫기 요청 후 진단이 출력됐다. 창/명령 종료와 포트 해제는 정상이지만 원인은 아직 확정하지 못했다. 하드웨어 가속·sandbox·로그를 끄지 않았다. 패키지 중복 출력의 잘못된 성공 표시, 빌드 파일 누락 시 일반 창 표시, 개발 서버의 작업 파일 감시/상위 work 폴더 차단 문제는 수정했다.

검증 범위는 현재 Windows PC와 새 프로젝트/앱 복사본이다. 앱 전용 연결 불가 프록시와 로컬 대조 요청으로 차단을 확인했으며 OS 전체 네트워크 설정은 변경하지 않았다. 별도 새 Windows/VM, 서명·설치 프로그램·공개 배포, 다중 모니터/실제 디스플레이 배율별 검증은 포함하지 않는다.

## Phase 1 — PDF Foundation

기본 실행 순서: 1.0 → 1.1 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6. 이번에는 사용자의 명시적 요청으로 Unit 1.5 확대·축소·너비 맞춤까지 진행했다. 1.0 전체 준비를 완료로 간주하지 않는다.

| Unit | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1.0 | 샘플 행렬·입력 정책 준비 | 합성 샘플과 가능하면 사용자 보유 샘플 구분, 기대 결과·암호/손상/용량 정책 기록 | 미착수 |
| 1.1 | PDF 파일 선택 | 취소·비PDF·권한 거부·크기 제한 처리; 선택한 파일만 읽기; 원본 불변. 기능 검사 통과, 기존 종료 오류는 별도 미해결 | 구현·기능 검사 통과 / 전체 완료 보류 |
| 1.2 | Drag & Drop | 드롭을 파일 선택과 동일한 검증 경로에 연결; 다중 드롭·폴더·빈 경로·URL 드롭 거절. 기능 검사 통과, 기존 종료 오류는 별도 미해결 | 구현·기능 검사 통과 / 전체 완료 보류 |
| 1.3 | PDF.js 렌더링 | 로컬 worker/자산으로 Canvas 표시; 한글·이미지·암호 요구·손상 처리. 기능 검사 통과, 기존 종료 오류는 별도 미해결 | 구현·기능 검사 통과 / 전체 완료 보류 |
| 1.4 | 페이지 이동 | 처음·이전·번호 입력·다음·마지막 이동; 범위 밖 정수·소수 거부; 빠른 연속 이동은 최신 요청 유지; 파일 교체는 1페이지 초기화. 기능 검사 통과, 기존 종료 오류는 별도 미해결 | 구현·기능 검사 통과 / 전체 완료 보류 |
| 1.5 | 확대·축소·너비 맞춤 | 50–200% 단계 배율·페이지별 너비 맞춤·고유 회전·DPI·창 크기 대응; 이전 렌더 취소; Canvas 상한; Viewer 하단/좌우 도구와 footer 안내. 기능·개발·빌드·패키지·실제 선택 창 통과. 최종 종료 15/18 | 구현·기능 검증 통과 / 전체 완료 보류 |
| 1.6 | PDF 기초 통합 검증 | 패키지에서 오프라인 PDF 표시; 자산 누락·정리·원본 해시·기본 성능 확인 | 미착수 |

Phase 1의 목표는 원문 Viewer이며 **현재 Unit 1.5는 선택·드롭한 PDF를 한 번에 한 페이지씩 이동하고 50–200% 확대·축소하거나 너비에 맞춰 표시**한다. 50 MiB 임시 입력 상한과 읽기 전용 전체 바이트 전달, PDF.js 구조 판정, 페이지 수, 암호 필요·손상 안내를 유지한다. Canvas backing bitmap은 최대 16,777,216픽셀·한 변 8,192픽셀로 제한한다. 파서·캐시·시간 예산과 전체 PDF 기초 통합 검증은 Unit 1.6에 남는다.

이 단계가 완성되면 원문 Viewer다. 가림 기능이 없는 상태를 CBT처럼 안내하지 않는다. 회전 버튼은 현재 추가하지 않으며 PDF가 가진 고유 회전은 올바르게 표시해야 한다. 다중 파일 드롭은 일괄 가져오기를 구현하지 않고 한 파일씩 열도록 안내한다.

## Phase 2 — PDF Analysis

**착수 전 구조 검토 필수.** 실행 순서는 **2.0 → 2.1 → 2.2 → 2.5 → 2.3 → 2.4 → 2.6**이다. 번호 크기와 실행 순서를 혼동하지 않는다.

| Unit | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 2.0 | 분석 경계·좌표·지원 범위 검토 | PDF 어댑터, 정규화 레코드, 페이지/문제 구분, 실패 상태·검증 계획 확정 | 미착수 |
| 2.1 | Text Content 추출·품질 분류 | 문자열·근거 추출, 페이지별 usable/insufficient/unknown; 한글 분절·혼합 페이지 검증 | 미착수 |
| 2.2 | Text Item 좌표 분석 | text/x/y/width/height/page 계약; PDF user space ↔ viewport; bbox 근사·회전·DPI 검증 | 미착수 |
| 2.5 | 분석 결과 Debug Overlay | 우선 text item bbox·페이지 정보 표시. 후속 Unit에서 생성되는 후보 레이어를 표시할 연결점만 마련 | 미착수 |
| 2.3 | 키워드 탐색 | 해설/풀이/정답/답/Answer/Solution/Explanation, 항목 분절·문맥·오탐 억제 검증 | 미착수 |
| 2.4 | 해설/정답 영역 추정 | 시작·끝 경계, A/B 순서, 복수 영역, 문제/보기 침범·그림 누락 검사; 근거·보류 사유 | 미착수 |
| 2.6 | 프로파일 지원 판정·검증 | 고정 지원 샘플과 미지원 샘플 분리; 누출·과다 가림·보류 비율 기록; CBT 착수 가능 여부 검토 | 미착수 |

Debug Overlay는 개발 진단 화면이다. 2.5에서 2.3·2.4 분석을 미리 구현하지 않는다. 키워드·영역 후보 표시는 해당 데이터가 구현되는 Unit에서 추가한다. 공개 전 정답 텍스트를 노출할 수 있으므로 일반 CBT 세션에서는 비활성화한다.

**검증 실패 시:** 샘플을 성공하도록 몰래 바꾸거나 고정 좌표를 일반 해법으로 넣지 않는다. 규칙 수정, 지원 프로파일 축소, 또는 Phase 4 수동 보정의 일정 변경을 제안한다. 측정 없는 범용 정확도를 주장하지 않는다.

### 첫 MVP 완료 조건

- [ ] 지원 형식의 파일 선택/드롭 → 페이지 렌더 → 가림 → 선택 변경 → 답 확인 → 해당 해설 공개 → 채점을 끝까지 수행한다.
- [ ] A/B 순서 및 4지/5지를 고정 샘플로 검증했다.
- [ ] 정답이 없거나 충돌하면 해설 공개와 채점을 분리하고 `채점 불가`로 안내한다.
- [ ] 지원 외·분석 중·오류 페이지에서 정답이 자동으로 먼저 드러나지 않는다. 원문 보기는 사용자가 명시적으로 선택한다.
- [ ] 선택·공개 상태는 페이지 이동/배율 변경 시 유지되며 PDF 교체·닫기 시 초기화한다.
- [ ] 첫 페이지, 다음 페이지, 빠른 이동, 배율/창 크기 변경, 렌더 지연에서도 마스크 준비 전 프레임 누출이 없다.
- [ ] 가린 텍스트의 선택/복사/접근성 경로와 Debug 화면 노출 정책을 검증했다.
- [ ] 오프라인 패키지에서 worker·글꼴·CMap 등 필요한 자산이 로컬 로드된다. 외부 요청·자동 전송이 없다.
- [ ] 원본 파일 사용 전후 해시가 같다. 미처리 오류·Console Error가 없다.
- [ ] 검증 환경, 샘플별 기대/실제 결과, 미지원 범위, 미실행 항목을 기록했다.

위 조건은 현재 통과한 것이 아니라 미래의 완료 기준이다.

## 기술 검증용 샘플 행렬

실제 문제 PDF는 제공되지 않았다. Unit 1.1의 입력 경계 시험용 작은 합성 PDF와 빈/위장/크기 경계 파일만 work에서 생성했다. 아래의 문서 유형별 전체 샘플 행렬을 준비하거나 PDF 렌더링 호환성을 검증한 것은 아니다. Unit 1.0에서 저작권 문제가 없는 합성 샘플을 준비하고, 사용자가 제공할 수 있는 대표 PDF는 로컬에서만 추가 검증한다. 서로 다른 실제 형식 3종 이상을 권장하지만 확보 전 일반화 성능을 주장하지 않는다.

| 샘플 | 확인할 위험 | 기대 처리 / 주 검증 Unit |
| --- | --- | --- |
| A형·4지, B형·5지 | 해설/정답 순서 차이 | 둘 다 가림·선택·공개·채점 / 2.4, 3.7 |
| 분리된 `정`+`답`, 한글·영문 제목 | 텍스트 항목 분절·정규화 | 근거를 유지한 후보 탐색 / 2.1, 2.3 |
| `정답을 고르시오`, 본문 속 Answer | 키워드 오탐 | 문제 지시문을 가리지 않음 / 2.3, 2.4 |
| 한 페이지 여러 문제·두 열 | 다른 문제의 답 동시 노출 | MVP 보류; 단일 문제로 오인하면 실패 / 2.6 |
| 문제/해설이 다음 페이지에 이어짐 | 잘못된 답 대응 | MVP 보류; 자동 연결하지 않음 / 2.6 |
| 해설 속 그림·수식, 키워드 없는 답 | 텍스트만 가려 누출 | 안전한 경계 없으면 보류 / 2.4, 2.6 |
| 스캔·빈 페이지·페이지 번호만 텍스트 | 스캔 오분류 | 분석 불충분 안내 / 2.1 |
| OCR 텍스트가 있는 스캔·혼합 문서 | 텍스트 존재와 품질 혼동 | 페이지별 품질 평가 / 2.1, 2.6 |
| 90/180/270도 고유 회전·view box 오프셋 | 좌표 변환 오류 | 렌더 일치; 분석 지원 밖이면 보류 / 1.5, 2.2 |
| 배율 50/100/200%, DPI 100/150/200% | Mask와 Canvas 불일치 | 노출·과다 가림 없는 정렬 / 2.2, 3.1 |
| 정답 없음·두 후보·범위 밖 답 | 잘못된 자동 채점 | known이 아니면 채점 불가 / 3.5, 3.6 |
| 손상·암호·권한 거부·비PDF·취소 | 예외·앱 멈춤 | 처리된 안내, 정상 파일로 복귀 / 1.1~1.3 |
| 이미지가 큰 PDF·장문 PDF·연속 파일 교체 | 메모리·늦은 결과 | 제한·취소·해제 동작 / 1.6, 3.7 |

배율/DPI 값은 검증 지점 예시이며 지원 범위 상한을 의미하지 않는다. 성능 예산·파일/Canvas 제한·분석 임계값은 해당 Unit에서 실제 환경을 측정한 뒤 이름 있는 설정으로 확정한다.

영역 검증은 기준 해설/정답 누락, 문제/보기 침범, 미지원 입력의 오승인, 자동 채점의 오류를 각각 센다. 보류 비율도 함께 보고하여 모든 입력을 보류한 시스템을 성공으로 평가하지 않는다. 지원 샘플은 모두 실제 풀이를 완료해야 하며 미지원 샘플은 안전한 보류가 통과 조건이다.

## 다음 착수 조건

이번 Unit 1.5의 배율·너비 맞춤·Viewer 배치 기능은 구현·검증했다. Node 검사 49개, 개발·빌드·패키지 Electron 3경로와 실제 Windows 선택 창 1개는 통과했다. 최종 종료 반복은 개발 모드 즉시 종료 3회에서 OPEN-09가 재현되어 15/18이다. 패키지 9/9와 개발 250ms·1500ms 6/6, 모든 종료 코드·포트 정리는 정상이다. 오류를 숨기거나 그래픽·보안 설정을 바꾸지 않았으므로 전체 무오류 완료 판정은 보류한다. Unit 1.0과 Unit 1.6 이후 기능은 이번 요청으로 진행하지 않는다.

이번에 확인한 현재 PC는 Node 24.20.0/npm 11.19.0이며 전역 설치는 변경하지 않았다. 실행과 재검증은 [README](../README.md)를 따른다. Unit별 검증 결과, 제한사항, 부채와 커밋 메시지 제안은 [CHANGELOG](CHANGELOG.md)에 기록한다.
